## MDMT 2.1.1

- **Fixes:**
  - Text files saved in older Windows encodings (Windows-1252, as written by Notepad before Windows 10 and by Word's plain-text export) are now read by Named Entities, Co-Words, Relationships and Translation. Named Entities, Co-Words and Relationships used to skip them without saying so, and Translation reported them as errors. Keyword Search reads keyword and filter files in these encodings too.
  - Named Entities, Co-Words and Relationships now list every file they skipped, and why (no text, as in a scanned PDF that needs OCR first, or a file that could not be read).
  - Co-Words: the summary report's links to documents in subfolders now work.
  - Named Entities writes each highlighted copy next to its document, so documents with the same name in different subfolders no longer overwrite each other's. In Named Entities and Co-Words, `report.pdf` and `report.txt` in the same folder get separate reports (the second one is named `report_2…`).
  - Relationships saves the text extracted from a PDF next to that PDF, as its page says, even for PDFs in subfolders, so later runs no longer count that text a second time. The File column of `relationships.csv` shows each file's path within the input folder. Text is now saved for PDFs only.
  - Keyword Search no longer stops with "All wedge sizes are zero" when one of the PDFs (a scanned one, for example) contains none of the keywords. Its charts say "No keywords found" instead, and the page says so when no keyword was found anywhere.
  - Keyword Search no longer skips PDFs whose extension is upper case (`.PDF`).
  - Relationships handles long documents much faster: splitting a book-length text into sentences used to take minutes and now takes a fraction of a second.
- **RAGBot** runs on the main release of llama-cpp-python (0.3.36). Answers are the same, and generation is slightly faster.
