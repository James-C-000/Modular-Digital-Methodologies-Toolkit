## MDMT 2.2.1

- **Keyword Search fixes:**
  - Filters now apply to the keywords as well as the text. With the basic filter on, keywords such as `o'brien` and `u.s.` used to find nothing, because the filter removed the apostrophe and the dots from the text but not from the keyword. A filter that removes `-` no longer loses hyphenated keywords. With the basic filter, `c++` is now searched as `c`.
  - Ligatures in a PDF's text (`ﬁ` in `ﬁeld`) and accents stored as a separate mark, as some PDFs store `café`, now match keywords typed normally.
  - Context rows keep hyphens as written: `mill-race` and `1843-1851` no longer become `mill race` and `1843 1851`. Counts are unchanged.
  - Keywords that match the same words, such as `york`, `york.` and `(York)`, are searched once. Before, each one counted the same matches again.
  - Searching is several times faster with many keywords.
  - A PDF whose charts cannot be saved, for example because the path is too long for Windows, no longer stops the search. It is listed with its counts kept. A `$` in a PDF's name or in a keyword no longer breaks the charts.
  - A keyword named `data_overview` gets its own CSV (`data_overview_2.csv`). On Windows and macOS it used to overwrite `Data_Overview.csv`.
  - Progress shows each PDF's path within the input folder, so PDFs with the same name in different sub-folders can be told apart.
  - When every PDF was skipped (scanned PDFs without text, for example), the page no longer says "None of the keywords were found".
- Files named just `.pdf`, `.md` or `.txt` (with nothing before the dot) are no longer treated as documents. RAGBot used to report them as unsupported.
